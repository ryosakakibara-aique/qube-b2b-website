# Figma → Screen Mapping

Verification of the screen scope declared in [CLAUDE.md](../../CLAUDE.md).

**Verified on:** working tree at commit `3f69dce`

**Method:** cross-referenced the declared routes against the route list Next.js generated into
`.next/types/routes.d.ts`, plus the on-disk `app/` tree.

## Route structure — VERIFIED

Every declared route exists, and **no undocumented route exists** except the `/cms` redirect.
The route-group directories (`(auth)`, `(cms)`) are organizational and correctly do not appear
in URLs, as CLAUDE.md states.

| Declared route | Figma node | Implemented at | Status |
| --- | --- | --- | --- |
| `/` | `1:1117` | `app/page.tsx` | ✅ route exists |
| `/products` | `1:1926` | `app/products/page.tsx` | ✅ route exists |
| `/products/[product]` | `1:2070` | `app/products/[product]/page.tsx` | ✅ route exists |
| `/cms/login` | `1:2265` | `app/(auth)/cms/login/page.tsx` | ✅ route exists |
| `/cms/products` | `1:2316` | `app/(cms)/cms/products/page.tsx` | ✅ route exists |
| `/cms/create` | `1:2372` | `app/(cms)/cms/create/page.tsx` | ✅ route exists |
| `/cms/edit/[product]` | `1:2525` | `app/(cms)/cms/edit/[product]/page.tsx` | ✅ route exists |

Next.js generated exactly this route set:

```
"/" | "/cms" | "/cms/create" | "/cms/edit/[product]"
    | "/cms/login" | "/cms/products" | "/products" | "/products/[product]"
```

### Two structural claims confirmed

1. **"There is no separate `/cms/products/[product]` screen."** Confirmed — no such route is
   generated, and no such directory exists.
2. **Dynamic segment naming.** The node `1:2070` is the product-detail screen, and the
   implemented dynamic segment is `[product]` (`app/products/[product]/page.tsx`, read via
   `params: Promise<{ product: string }>`). The CMS edit route uses `[product]` as well, not
   `[slug]` or `[id]` — consistent with the declared scope.

## Undocumented route — needs a decision

`/cms` is generated by `app/(cms)/cms/page.tsx`, which is a 5-line redirect to
`/cms/products`. CLAUDE.md does not list a `/cms` screen.

This is almost certainly intentional (a natural entry-point redirect), but it is an
undocumented route and therefore a small deviation from "do not invent additional screens."
Either document it as a redirect or remove it.

## Node ID → frame correspondence — NOW VERIFIED

Originally unverifiable (live Figma access returned 403 and no credentials were available). The
gap was closed by the SVG exports in [`screenshots/`](screenshots/): each file carries its
source node ID inside its `clip-path`/`mask` identifiers — e.g. `clip0_1_2265` in
`cms-login.svg` confirms node `1:2265`. That is authoritative, self-identifying metadata.

All 10 nodes listed in [FIGMA.md](../../FIGMA.md) were confirmed this way. See
[DESIGN-REFERENCE.md](DESIGN-REFERENCE.md) for the confirmed inventory with frame dimensions.

### Remaining limitation

Node correspondence is confirmed, and **color + geometry are fully extractable** from the SVGs.
**Typography and copy text are not** — Figma outline-converted all text to `<path>`, so there
are zero `<text>`/`font-size`/`font-family` occurrences across all 10 files. Visual comparison
still requires an image-capable model.

## Related documentation drift

Found while verifying — these affect how the mapping should be read:

- **`ARCHITECTURE.md` (tracked, deleted in working tree) is stale and contradicts CLAUDE.md.**
  It describes `/products/[id]`, `/cms/[product]/edit`, and `/cms/products/[product]`-style
  nesting that do not exist. CLAUDE.md explicitly states there is no separate
  `/cms/products/[product]` screen. If architecture documentation is wanted, it must be
  rewritten to match the verified route set above, not restored as-is.
- **`AGENTS.md` (tracked, deleted in working tree) is auto-generated by Next.js.** Its own text
  states it is re-added by `next dev`. Deleting it only recreates an uncommitted change on the
  next `next dev` run; committing it alongside other work keeps the tree clean. This is why it
  still shows as deleted-but-unstaged.
- **`node_modules/next/dist/docs/` is a real, authoritative Next 16 reference** bundled with
  the installed version (16.3.4), written by `next/dist/server/lib/generate-agent-files.js`.
  Consult it before writing Next.js code — several conventions differ from older training data
  (notably `proxy.ts` in place of `middleware.ts`).
